# План: стабильные вход, регистрация, загрузки и работа из РФ/РБ/КЗ

## Состояние сейчас
- Lovable Cloud уже подключён к проекту (ключи и клиент присутствуют), отдельное включение не требуется.
- В сети клиента повторяются `POST /auth/v1/token?grant_type=refresh_token` с `Failed to fetch` каждые ~20 секунд — цикл обновления сессии не останавливается при сетевой ошибке.
- В рантайме есть ошибка `Lock broken by another request with the 'steal' option` — несколько вкладок/экземпляров клиента одновременно борются за блокировку обновления токена.
- Базовый слой устойчивости частично есть: `withTimeout`, `getAuthErrorMessage`, `uploadAttachment` с прогрессом и отменой, `ConnectionBanner`. Он не покрывает повторные попытки, backoff и региональные задержки.

## Что делаю

### 1. Стабилизация сессии и устранение шторма refresh
- Настроить клиент Supabase: собственный `storageKey`, отключить конфликтующий захват блокировки между вкладками, включить `detectSessionInUrl` только там, где он нужен.
- Останавливать автоматическое обновление токена при `offline` и после серии сетевых ошибок; возобновлять по событию `online` и при возврате вкладки в фокус.
- Убрать ошибку `Lock broken ... 'steal'`: обновление сессии выполняет только активная вкладка, остальные слушают изменения через `onAuthStateChange`.

### 2. Вход и регистрация
- Единая обёртка запроса: таймаут, до 2 повторов только для сетевых сбоев (не для неверного пароля и не для повторной регистрации).
- Понятные русские сообщения и кнопка «Повторить» без потери введённых данных.
- Блокировка повторной отправки формы во время запроса, чтобы не создавать дубли аккаунтов.

### 3. Загрузки файлов и видео
- Перевести все пути загрузки (сообщения, голосовые, вложения каналов, видео стримов) на общий helper `uploadAttachment`.
- Добавить в helper: chunk-friendly таймаут по размеру файла, повтор при обрыве, стабильный путь объекта (чтобы retry не плодил дубликаты), полный сброс input/прогресса/ETA после успеха, отмены или ошибки.
- Не создавать сообщение или пост, пока файл не подтверждён хранилищем.

### 4. Ускорение для России, Беларуси, Казахстана
Замедление в этих странах вызвано длинной задержкой до облака и фильтрацией долгих соединений, поэтому фокус на снижении числа и длительности запросов:
- Увеличенные, но конечные таймауты и экспоненциальный backoff с jitter для повторов — вместо бесконечных зависших запросов.
- Убрать N+1 обращения: профили, реакции и счётчики непрочитанных получать пакетно одним запросом.
- Дедупликация параллельных обновлений списков и отбрасывание устаревших ответов при смене чата или канала.
- Realtime: одна управляемая подписка на контекст, обработка `TIMED_OUT`/`CHANNEL_ERROR`/`CLOSED` с единственным циклом переподключения; при недоступном Realtime — редкий polling только для открытого чата и его отключение после восстановления.
- Пауза heartbeat и опросов в скрытой вкладке.
- Индикатор качества соединения с ручным повтором вместо перезагрузки страницы.

## Проверка
- Вход, регистрация, выход: успех, неверные данные, offline, таймаут, восстановление сети.
- В сетевой панели после ошибки нет повторяющегося цикла refresh, ошибка `Lock broken` не воспроизводится.
- Загрузка файла: успех, отмена, таймаут, повтор — без зависшего прогресса и дубликатов.
- Проверка чата, канала и стрима в браузере через Playwright со снимками экрана.

## Технические детали
Изменения только на клиенте (React/Vite) и в общем сетевом слое `src/lib/network.ts`, `src/lib/resilient-upload.ts`, `src/integrations/supabase/client.ts`, `src/contexts/AuthContext.tsx`, `ConnectionContext` и хуках данных. Автоповторы применяются исключительно к идемпотентным чтениям; любые записи повторяются только по явному действию пользователя. Миграции БД не требуются.
